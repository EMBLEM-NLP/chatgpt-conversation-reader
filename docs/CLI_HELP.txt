================================================================================
gcr 0.2.0-dev.0 - read, search and annotate your own ChatGPT export data,
  offline

Usage:
  gcr <command> [options]
  gcr help [command]

GCR works on conversations you imported from an official export. It never
contacts chatgpt.com, never sends a message and never reads browser data: a
chatgpt.com link is only a key into the data you imported.

Commands:
  doctor                Check this machine and the database; list what GCR
                        supports and what it does not.
  import                Import an official ChatGPT (or Claude) export into the
                        local database.
  import-copy           Index a manual copy of a conversation (Mode B). Always
                        marked partial.
  batches               List the import batches in the database (one per
                        distinct export imported).
  list                  List imported conversations.
  get                   Show one imported conversation (its active thread, or
                        every branch).
  search                Full-text search over message text, conversation titles
                        and attachment file names.
  branches              List the branches of a conversation (edited prompts,
                        regenerated answers).
  thread                Show one branch of a conversation as a message thread.
  stats                 Count messages by role, model, channel, day,
                        conversation, provider or content type.
  audit                 Check the imported data for gaps: missing models, empty
                        or untitled conversations, broken trees.
  graph <command>       Knowledge graph: build, query, path, neighbors,
                        god-nodes, explain, export.
  draft <command>       Local drafts (never sent): create, list, show, archive.
  annotate <command>    Local notes on conversations and messages: create,
                        update, list, show.
  mcp                   Run the local MCP server on stdio over the database.
  help                  Show help for a command: gcr help <command>.

Global options (before or after the command):
      --db <path>               SQLite database file. (default: $GCR_DB, else
                                ./.gcr/gcr.sqlite)
      --format <format>         Output format. compact is token-light plain
                                text; jsonl is one JSON value per line. One of:
                                json, markdown, compact, jsonl. (default:
                                markdown)
      --tz <IANA>               Time zone for human-readable times (for example
                                Europe/Berlin). JSON keeps UTC. (default: UTC)
      --quiet                   Suppress non-essential notes on stderr. Errors
                                are always printed.
      --debug                   Print stack traces on stderr when a command
                                fails (sets GCR_DEBUG=1).
  -h, --help                    Show help for this command and exit.
  -V, --version                 Print the version and exit.

Examples:
  gcr import ~/Downloads/chatgpt-export.zip
      Import an official export into ./.gcr/gcr.sqlite.
  gcr list --limit 10
      The ten most recently updated conversations.
  gcr get 00000000-0000-4000-8000-000000000001
      Print one imported conversation.
  gcr search "release notes" --format json
      Full-text search, machine-readable.

Exit codes:
  0   success
  1   INTERNAL_ERROR
  2   INVALID_ARGUMENT
  *   The full table, per error code, is in docs/CLI_REFERENCE.md; each command
      lists the codes it can return.

Run "gcr help <command>" for the options, examples and exit codes of one
command.

gcr doctor - Check this machine and the database; list what GCR supports and

Usage:

  -h, --help                    Show help for this command and exit.

Examples:

      Check the environment and the default database.
  gcr doctor --db ./work.sqlite --format json
      Inspect a specific database file, machine-readable.

Exit codes:
  0   success
  1   INTERNAL_ERROR
  2   INVALID_ARGUMENT
  *   doctor exits 0 when every check passes, 5 when the inspected database is

gcr import - Import an official ChatGPT (or Claude) export into the local
  database.

Usage:
  gcr import <path> [options]

The input is the ZIP you downloaded from ChatGPT (Settings > Data controls >

                                the file. One of: chatgpt, claude. (default:
                                detected from the file)

                                manifest problem is found (default: record it as
                                a warning and continue).

$ gcr get --help
================================================================================
gcr get - Show one imported conversation (its active thread, or every branch).

Usage:
  gcr get <ref> [options]

The active thread is chosen by the export's own current-node pointer. If the
export has none and the conversation has several branches, GCR refuses to guess
(ACTIVE_BRANCH_UNKNOWN) unless you pass --branch, --all-branches or
--branch-policy.

A chatgpt.com link succeeds only if that conversation is in your database;
otherwise the command fails with NOT_IN_LOCAL_EXPORT. GCR never contacts
chatgpt.com.

Every format lists the same warnings as the SDK and the MCP tools;
SOURCE_NOT_FULL_HISTORY comes first when the source is a partial copy or a
rendered-only export. Messages that no root reaches (a damaged tree) are stored
and searchable but cannot be shown here: the warning NO_BRANCHES says so.

Arguments:
  <ref>                         Conversation UUID or an exact
                                https://chatgpt.com/c/<uuid> link. The link is
                                only a key into data you imported; nothing is
                                fetched.

Options:
      --branch <id>             Show this branch (a branch id is the id of its
                                leaf message; list them with "gcr branches").
      --branch-policy <policy>  Opt in to a labelled heuristic when the export
                                does not say which branch was active: last_child
                                follows the last child from the root,
                                latest_leaf takes the newest leaf. The result
                                carries the warning ACTIVE_BRANCH_HEURISTIC. One
                                of: last_child, latest_leaf. (default: none: GCR
                                never guesses the active branch)
      --all-branches            Also show every other branch (edited prompts,
                                regenerated answers). With --format json the
                                result holds one thread per branch.
      --include-hidden          Include messages the export marks as hidden
                                (system scaffolding, memory, ...).
      --batch <id>              Read this import snapshot (a batch id from "gcr
                                batches") instead of the newest one.
      --provider <provider>     Disambiguate when the id exists under several
                                providers. One of: chatgpt, claude, openai_api.
      --account <label>         Disambiguate when the id exists under several
                                accounts.
      --stored-id               Take the conversation as an id exactly as "gcr
                                list" prints it. Needed only for ids that are
                                not UUIDs (for example one GCR synthesized for
                                an export that had none). Links are not accepted
                                with this switch.

Global options:
      --db <path>               SQLite database file. (default: $GCR_DB, else
                                ./.gcr/gcr.sqlite)
      --format <format>         Output format. compact is token-light plain
                                text; jsonl is one JSON value per line. One of:
                                json, markdown, compact, jsonl. (default:
                                markdown)
      --tz <IANA>               Time zone for human-readable times (for example
                                Europe/Berlin). JSON keeps UTC. (default: UTC)
      --quiet                   Suppress non-essential notes on stderr. Errors
                                are always printed.
      --debug                   Print stack traces on stderr when a command
                                fails (sets GCR_DEBUG=1).
  -h, --help                    Show help for this command and exit.

Examples:
  gcr get 00000000-0000-4000-8000-000000000001
      Print the conversation as Markdown.
  gcr get https://chatgpt.com/c/00000000-0000-4000-8000-000000000001 --format json
      Look a link up in your local data and print JSON (fails with
      NOT_IN_LOCAL_EXPORT if it was never imported).
  gcr get 00000000-0000-4000-8000-000000000001 --all-branches --format compact
      Every branch in token-light text.
  gcr get 00000000-0000-4000-8000-000000000001 --branch-policy latest_leaf
      Opt in to the newest-leaf heuristic when the export has no current node.

$ gcr search --help
================================================================================
gcr search - Full-text search over message text, conversation titles and
  attachment file names.

Usage:
  gcr search <query> [options]

The query is treated as plain words (operators and quotes are inert; a trailing
* makes a prefix). Case and accents are ignored and CJK text matches by
character. Use --raw to pass SQLite FTS5 syntax through.

Folded when matching: case, accents, character width (fullwidth letters),
ligatures (fi) and CJK substrings. Not folded: "ß" is not "ss". Emoji and other
symbols are not indexed (only letters, digits and combining marks are), so a
query made only of them is refused with INVALID_ARGUMENT: search for words.

--scope attachments matches the file NAMES and MIME types of attachments
(metadata only: attachment files are never read and no attachment content is
searched, not even the text a Claude export carries inline; a ChatGPT export may
not contain the files). Each search word must occur anywhere inside the folded
name or type (so "notes", "ynthetic-note" and "synthetic-notes.txt" all find
synthetic-notes.txt, "diagram" finds synthetic-diagram.png, and "image/png"
finds every PNG). Results are not ranked: oldest message first. --scope all
lists titles, then messages, then attachments (attachment names are part of
"all"); with --raw the attachment part is skipped and ATTACHMENTS_NOT_SEARCHED
says so.

Hidden messages (and their attachments) are skipped unless --include-hidden. A
query that starts with "-" goes after "--".

Arguments:
  <query>                       Words to search for (quote it when it has
                                spaces).

Options:
      --raw                     Pass the query to SQLite FTS5 unchanged
                                (AND/OR/NEAR/phrases). A syntax error is
                                FTS_SYNTAX_ERROR.
      --scope <scope>           Search message text, conversation titles,
                                attachment file names and MIME types, or all
                                three (titles, then messages, then attachments).
                                One of: messages, titles, attachments, all.
                                (default: messages)
      --role <role>             Only messages by this author role (user,
                                assistant, system, tool, ...). Messages and
                                attachments scopes only.
      --channel <channel>       Only messages on this channel (for example
                                final). Messages and attachments scopes only.
      --has-model               Only messages whose export states the model
                                explicitly. Messages and attachments scopes
                                only.
      --conversation <ref>      Only inside this conversation (UUID, chatgpt.com
                                link or stored id). Messages and attachments
                                scopes only.
      --after <ISO>             Only messages created at or after this ISO-8601
                                UTC time. Messages and attachments scopes only.
      --before <ISO>            Only messages created before this ISO-8601 UTC
                                time. Messages and attachments scopes only.
      --include-hidden          Include messages the export marks as hidden
                                (system scaffolding, memory, ...).
      --all-batches             Include superseded import snapshots, not only
                                the newest one of each conversation (the same
                                message can then appear once per snapshot).
      --provider <provider>     Only conversations of this provider. One of:
                                chatgpt, claude, openai_api.
      --account <label>         Only conversations imported under this account
                                label.
      --limit <n>               Maximum number of hits (1-200). (default: 20)
      --offset <n>              Number of results to skip (paging). (default: 0)
      --cursor <cursor>         Continue after the `nextCursor` printed by the
                                previous page (messages scope only; the other
                                scopes page with --offset).

Global options:
      --db <path>               SQLite database file. (default: $GCR_DB, else
                                ./.gcr/gcr.sqlite)
      --format <format>         Output format. compact is token-light plain
                                text; jsonl is one JSON value per line. One of:
                                json, markdown, compact, jsonl. (default:
                                markdown)
      --tz <IANA>               Time zone for human-readable times (for example
                                Europe/Berlin). JSON keeps UTC. (default: UTC)
      --quiet                   Suppress non-essential notes on stderr. Errors
                                are always printed.
      --debug                   Print stack traces on stderr when a command
                                fails (sets GCR_DEBUG=1).
  -h, --help                    Show help for this command and exit.

Examples:
  gcr search "marsupial habitat"
      Messages containing both words, best match first.
  gcr search roadmap --scope titles --format json
      Conversation titles that mention "roadmap".
  gcr search "report pdf" --scope attachments
      Attachments whose file name or type contains both "report" and "pdf"
      (metadata only).
  gcr search "quok*" --role assistant --after 2025-01-01T00:00:00Z --limit 5
      Prefix match, assistant messages from 2025 on.
  gcr search --conversation 00000000-0000-4000-8000-000000000001 -- "-draft"
      Inside one conversation; "--" lets the query start with a dash.

Exit codes:
  0   success
  1   INTERNAL_ERROR
  2   INVALID_ARGUMENT, INVALID_URL, INVALID_UUID, UNSUPPORTED_URL,
      FTS_SYNTAX_ERROR
  5   DB_NOT_FOUND, DB_SCHEMA_TOO_NEW, DB_ERROR

stdout carries only the result; notes and errors go to stderr. GCR never
contacts chatgpt.com.

bounded by --depth and --max-nodes, and truncation is reported.

gcr mcp - Run the local MCP server on stdio over the database.

Usage:
  gcr mcp [options]

Speaks the Model Context Protocol over stdin/stdout for an MCP client such as VS
Code or Codex. While it runs NOTHING but JSON-RPC is written to stdout; logs go
to stderr. The database is opened read-only unless --allow-local-writes is

itself and then exits 0 after closing the database.

                                ./.gcr/gcr.sqlite)

      --debug                   Print stack traces on stderr when a command
                                fails (sets GCR_DEBUG=1).
  -h, --help                    Show help for this command and exit.
