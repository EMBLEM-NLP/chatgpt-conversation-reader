# Parity matrix and evidence register

This document classifies every requirement of `SPEC.md` (FR-01 to FR-17, NFR-01 to NFR-08, and the capability modes A to E of section 3) and every feature of the Claude Conversation Reader (CCR) against what this repository actually contains. It answers the Phase 0 instruction of `CODEX_TASK.md` ("for every requirement, classify supported, synthetic-only, experimental, not implemented, blocked by platform, and add tests/evidence links") and deliverable F ("parity + risk/coverage report").

Written 2026-10-11 (UTC) for GCR `0.2.0-dev.0` (`package.json`). Every statement of the form "ran" below, except the "(run)" tags in section 4 (see its introduction), was executed by the author of this document in this session on Linux x86_64 with Node.js v22.22.0 and npm 10.9.4. Statements that no command here supports are marked `NOT VERIFIED`.

**This is not a claim of live integration.** GCR has never been run against a real ChatGPT export, never connected to a real MCP host product, and its GitHub Actions workflow has never run on GitHub. Passing tests on invented data prove internal consistency, not compatibility. The platform policy review was not performed (`docs/SECURITY_AND_BOUNDARIES.md`, section 6).

Related documents: `SPEC.md`, `CODEX_TASK.md`, `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/SECURITY_AND_BOUNDARIES.md`, `docs/BROWSER_GATE.md`, `docs/IMPORT_FORMAT.md`, `docs/ADAPTERS.md`.

## 1. Legend and evidence policy

### 1.1 The five statuses

| Status | Definition (all conditions must hold) |
|---|---|
| **supported** | The behaviour is implemented; automated tests that were run in this session cover it with positive and negative cases and passed; and what the requirement's acceptance text asks for does not depend on a fact about an outside system (the real ChatGPT export format, a third-party MCP host product, a platform policy) that nobody has observed. Known gaps are written in the Gaps column; a gap that contradicts a word of the SPEC is marked `DEVIATION`. |
| **synthetic-only** | Implemented and tested, but only against data or behaviour that the authors wrote from secondary descriptions of an outside system (community notes about the export format, documented CCR data shapes). No live export, live client or primary source was used. Passing tests show the code is consistent with its own assumptions, not that the assumptions are true. Real input may fail or lose information in ways no test here can show. |
| **experimental** | Implemented but explicitly unstable or unreviewed, so users must not rely on it. **No requirement is classified experimental.** (The `node:sqlite` module that GCR depends on is flagged experimental by Node.js itself; that is a risk, listed in `docs/SECURITY_AND_BOUNDARIES.md` section 9, not a feature status.) |
| **not implemented** | No code exists for a required behaviour, or only a disabled stub that throws `NOT_IMPLEMENTED`. Deliberately gated behaviour (FR-17) is in this class. |
| **blocked by platform** | Cannot be built or verified from the repository because it needs a live export from a consenting user, a primary-source reading of the platform's terms, or a platform route that no supported mechanism offers. A human has to act outside the repository. |

### 1.2 How a row gets its status

* The Status column is the status of the weakest **core** behaviour named by the requirement sentence and its acceptance text in `SPEC.md` (sections 4 and 8).
* Parts that the SPEC makes optional ("or", "optional") do not lower the row. They are listed in section 2.4 with their own status.
* "Blocked by platform" parts of a row are listed in section 6; the row itself keeps the status of what exists.
* Where a row mixes statuses, section 2.4 splits it.

### 1.3 Evidence policy

1. Evidence is a repository path of a test or script plus the command that runs it. Only runs that this document's author executed in this session are called "ran"; anything else is "cited, not re-run".
2. Tests that use invented data (everything under `fixtures/` and `test/helpers/`) are never evidence that a live export or client behaves the same way.
3. Another document's statement is not evidence. Where this document repeats one it says so.
4. A claim that no command here supports carries `NOT VERIFIED`.
5. Numbers are copied from output with their date and Node version. None is estimated.

### 1.4 How to re-run

```bash
npm ci                                  # NOT run by the author of this document
npm run build:test                      # compiles src/ and test/ to dist-test/
node --test --test-concurrency=2 "dist-test/test/domain/ids*.test.js"        # one group of files
node --test --test-concurrency=2 "dist-test/test/**/*.test.js"               # everything (npm test does build:test first)
node scripts/ci-smoke.mjs               # needs npm run build first
node scripts/privacy-scan.mjs --root .  # needs npm run build first
```

Paths in the Evidence columns are source paths under `test/`; the compiled copy lives at the same path under `dist-test/test/` with `.js`.

## 3. CCR to GCR feature parity

### 3.1 Method, license boundary and totals

* The reference is `EMBLEM-NLP/claude-conversation-reader-public` at commit `f66e24e06b15e75060a65b2bf9b646395ddac0d1`, read in a local read-only checkout. Source links below are pinned to that commit. A path in a column headed "CCR source" or "CCR location" is relative to the CCR repository root; it does not exist in this repository (all of them exist in the CCR checkout).
* **No CCR code was copied** (ADR-0008). CCR has no LICENSE file; its `package.json` says `ISC` without a license text or a named holder, so no reuse right is assumed. This document describes behaviour in original words and links to CCR lines as references only.
* Counts come from the CCR code: 49 registered CLI commands (`grep -c "^  \.command("` on `src/index.ts`) and 33 MCP tools (`grep -c "server.tool("` on `src/mcp/tools.ts`). Older counts in CCR's own headers and docs (39 commands, 22 or 25 or 27 or 30 tools) are stale.
* Classes: **Equivalent** = GCR has a command or tool with the same job on the same kind of input (local data); **Different by design** = GCR meets the need another way, or deliberately changes the behaviour, and says how; **Deferred** = no boundary conflict but not implemented in this version; **Out of scope (auth/cookies/network)** = the CCR feature needs the provider's session cookies, a private endpoint, browser automation or another network service, which GCR forbids (`AGENTS.md`, `SPEC.md` section 9, `CODEX_TASK.md` stop conditions).

| | Equivalent | Different by design | Deferred | Out of scope | Total |
|---|---|---|---|---|---|
| CLI commands | 15 | 6 | 7 | 21 | 49 |
| MCP tools | 10 | 10 | 5 | 8 | 33 |

Twelve of CCR's 33 MCP tools use the live API (per the research notes, which read the code; nothing in CCR was run by this author); four of those (`list_conversations`, `get_conversation`, `search_conversations`, `get_conversation_as_context`) have a local-data GCR equivalent, and eight are out of scope. "Equivalent" never means the same data source: every GCR counterpart reads the user's imported export.
